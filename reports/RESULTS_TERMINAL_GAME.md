# Offline Terminal Game: Preliminary Experiment

2026-10-28 · Public research record. Game and experimental source code remain private.

## Specimen and method

A small text game accepts numeric movement commands and links separately against unprotected, manually split, manually encoded, and simple-VM logic. It calculates collision damage and updates 200 enemies. This is a turn-based terminal game, not a commercial engine or a 3D game. The experiment does not test automatic application of a protector to arbitrary games.

After 500 scripted inputs, all four variants produced the same screen SHA-256. An interactive input/output path was also checked in the unprotected build using a movement input and a quit command. The performance path restarted after health reached zero and executed 6,000 updates. Final state and restart counts agreed across all four builds. These checks do not prove complete behavioral equivalence.

## Game-loop measurement

Each variant ran five times in randomized order on WSL2 with GCC 15.2.0 `-O2`. Every run measured 6,000 updates and in-memory text-frame generation. Terminal output, input waiting, OS display work, and graphics rendering were excluded. The table reports the median of run medians and the median of run 95th percentiles, in microseconds.

| Variant | Median | 95th percentile | Median relative to baseline |
| --- | ---: | ---: | ---: |
| Unprotected | 0.85 μs | 1.16 μs | 1.00× |
| Function splitting | 1.18 μs | 1.59 μs | 1.39× |
| Data encoding | 2.04 μs | 2.73 μs | 2.40× |
| Simple VM | 15.439 μs | 39.13 μs | 18.16× |

![Game update-time comparison](figures/arcade-performance.png)

Dots show run medians; red marks show the median across five runs. The horizontal axis is logarithmic. These values are not FPS or displayed frame times and may vary with scheduling. The small repetitive workload cannot predict another game's performance. VM function visibility was changed for linking into the benchmark.

## Developer impact

Five compile/link runs with debug symbols gave medians of 189.4 ms for unprotected code, 182.9 ms for splitting, 185.4 ms for encoding, and 221.0 ms for the VM. Variability is substantial in such a small project. Manual transformation, setup, and verification effort are excluded, so the figures should not be used as overall adoption costs.

GDB reached a logic-entry breakpoint and displayed the game call stack in all four builds. The VM stopped in generated interpreter source. Mapping back to original logic, difficult bug investigation, build-pipeline work, update compatibility, and engine integration were not measured. These debug builds must be distinguished from the separate distribution binaries without debug symbols.

## Evaluation without source disclosure

Two separate evaluators received the original single-function CLI binary or its simple-VM version and the input/output interface. Both used REA/Ghidra and produced independent programs. A further 260 integer inputs generated by the primary investigator matched each original binary's stdout and exit code. The inputs were generated separately from evaluator preparation, but they do not prove equivalence for the full input space. The target was the logic CLI, not this entire terminal game.

Evaluators reported approximately 75 seconds for unprotected logic and 84 seconds for the VM. **There was only one attempt per condition, and they shared REA/Ghidra resources on the same machine concurrently. These times cannot establish a protection advantage.** Repeated trials with comparable models, environments, and resource budgets are needed. Evaluators received neither source nor previous conversation history and were instructed not to read other folders, but file access was not blocked by the OS. Training-data contamination was not checked.

This simple VM did not prevent reconstruction. Trials without source disclosure for splitting and data encoding, and reconstruction of the entire game, were not performed in this study. The earlier source-aware results are recorded in the [existing-techniques report](RESULTS_EXISTING_METHODS.md).

Implementation, binaries, and raw experimental artifacts remain private. Publication is limited to reviewed reports and figures.
