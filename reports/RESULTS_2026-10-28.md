# Offline Protection: Initial Experiment

This is a public results report. Experimental code remains private.

## Question

How do simple implementations of established techniques affect REA analysis and normal execution? All three variants implement the same small state-transition calculation, not a complete game.

## Results

| Variant | Median per logic call | Relative to baseline | REA observation |
| --- | ---: | ---: | --- |
| Unprotected | 5.846 ns | 1.00× | Core calculation decompiled. |
| Manual control-flow sample | 5.744 ns | 0.98× | Core calculation exposed directly again. |
| Simple VM | 107.929 ns | 18.46× | Interpreter and instruction data were readable. |

Each value is the median of seven randomly ordered runs of ten million consecutive calls in the same WSL environment: GCC 15.2.0, `-O2`, x86-64. The variants used the same call interface and produced the same final results. The VM function's visibility was changed for separate compilation. These are not frame-time or whole-game measurements. All three variants agreed on 1,004 boundary and random inputs.

REA with Ghidra 12.1.4 exposed a direct calculation in the control-flow sample. Compiler optimization appears to have removed the manual structure, but individual optimization passes were not traced. Reconstruction time and success rates were not compared. The earlier VM reconstruction was performed by an investigator who had already seen the source; its agreement on 302 inputs was not an independent trial.

The observations show execution costs in this simple VM and a failure mode of this manual control-flow implementation. They do not evaluate all VM protection or control-flow obfuscation, or establish that analysis resistance can be added without normal execution overhead.

## Requirements for later trials

Add other researched techniques and verify that intended transformations survive compilation. Use evaluators without source disclosure, equal time/tool conditions, repeated reconstruction attempts, and held-out inputs. Measure game frame time, loading and memory separately from developer build and debugging effort.
