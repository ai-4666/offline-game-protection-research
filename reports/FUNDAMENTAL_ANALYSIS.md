# 오프라인 게임 복제 방어: 기초 원리와 실험

2026-10-28 · 공개 연구 기록. 코드와 실행 파일은 공개하지 않는다.

## 문제를 세 가지로 분리

1. 원본 파일·에셋·보호된 모듈을 그대로 복사해서 쓰는 것.
2. 파일을 분석하거나 실행 중 상태를 관찰해 동등한 코드를 재구현하는 것.
3. 플레이와 입력·출력을 관찰해 비슷한 게임을 새로 구현하는 것.

이 세 문제는 다르다. 코드 난독화의 효과가 확인되어도 관찰 기반 재구현이 막힌다는 뜻이 아니다. 오프라인 게임은 사용자 기기에서 실행해야 하므로, 소프트웨어만으로는 동작에 필요한 코드와 데이터 또는 그 실행 결과가 공격자의 관찰 범위에 들어간다. 복잡한 행위는 유한한 관찰로 완전히 배우기 어려울 수도 있으나, 이를 곧 안전성으로 가정할 수 없다. 특정 플랫폼 하드웨어의 별도 신뢰 경계가 있다면 모델을 따로 정의해야 한다.

## 이론과 한계

Barak 등의 논문은 특정한 엄밀한 정의인 일반 목적 가상 블랙박스 난독화를 모든 프로그램에 적용할 수 없음을 보였다. 이것이 모든 개별 게임의 분석이 쉽다는 증명이나, 모든 난독화가 쓸모없다는 증명은 아니다. 또한 이 정리 자체가 게임의 관찰 기반 복제가 항상 가능하다는 증명도 아니다. [원 논문](https://www.cs.ucla.edu/~sahai/work/web/2001%20Publications/Crypto_Barak2001.pdf), [저자 해설](https://www.boazbarak.org/papers/obf_informal).

방어 목표를 정할 때 공격자가 얻는 것(원본 실행 파일, 추출된 조각, 관찰 가능한 화면·입력), 성공 조건(동등 기능, 특정 게임 경험, 코드·에셋 복사), 시간과 하드웨어 예산을 먼저 고정한다. 분석자에게만 부담을 지우고 정상 플레이·개발 비용은 정확히 0이라는 주장은 별도 증명이 없는 한 하지 않는다.

## 소규모 입출력 관찰 예비 실험

이번 변환 시제품을 직접 실행해 입출력만 수집하는 별도 테스트를 수행했다. 분석자는 출력의 필드 배치와 가능한 계산식의 작은 후보 범위를 미리 알고 있었고, 30개 임의 입력 뒤 추가로 21개의 선택 입력을 넣었다. 그 결과 후보 범위 안에서 단일 식이 남았고, 다른 300개 32비트 정수 입력에서 같은 출력을 냈다. 이 실험은 사전 지식이 큰 인위적인 작은 로직의 제한된 관찰 공격이며, 일반 게임을 51회 관찰해 재구현할 수 있다는 의미가 아니다. 반면 코드 난독화와 무관하게 실행 결과 자체가 정보를 줄 수 있음을 이 샘플에서 보여준다.

## 실험 연구 방향

- 정적 분석만 허용, 동적 관찰 허용, 입출력만 허용, 모듈 복사 허용 조건을 별도로 평가한다.
- 같은 입력 예산과 시간에서 재구현 성공률을 비교하고, 장기 게임 상태와 알려지지 않은 입력을 분리해 평가한다.
- 보호 전·후 기능 일치와 자동 세이브/재시작도 확인하고, 실제 엔진의 프레임 시간·메모리·플랫폼 호환성 및 개발자의 빌드·디버깅 부담을 측정한다.
- 여러 시드로 빌드를 만들어도 한 빌드의 모듈·동작이 그대로 재사용 가능한지 별도 검사한다. 바이너리 해시가 다르다는 사실만으로 다양화 효과를 주장하지 않는다.
- 하드웨어나 온라인 신뢰 서비스를 도입하면 완전 오프라인 조건과 플레이어 제약이 바뀌므로 별도 선택과 평가가 필요하다.

지금까지의 표, VM, 다양화 시제품은 범용 오프라인 게임 복제 불가능을 달성하지 못했다. 다음 가설은 개별 난독화 트릭이 아니라 특정한 공격자의 관찰과 자원, 실제 보호할 게임 요소에 근거해 세운다.
